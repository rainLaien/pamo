# 第十三轮：残余尺寸缺陷的诊断与继续处理

## 结论

目标仍未完成。原始 STL 全流程 **102.0560 秒**，超过 90 秒。新候选解决了第十二轮的四条残余尺寸长边，但有区域质量退化，仍不采纳；`SizeFeasibleFinalRefine` 默认关闭。

## 证据与实现

第一步只添加报告字段：最终细分停止原因，以及残余长边是否在选中区域外。相同修复分区上的诊断输出与第十二轮输出 SHA256 完全一致，四条长边均在已选区域内。由此排除了本例的邻域遗漏假设，停止原因是 `no_selected_size_progress`。

第二步对候选的长边数量、最大边比之外增加超长程度平方和：对超过原有长边容差的边，累计 `(length/target - splitRatio)^2`。仅实验开关允许在数量和最大比值不变时，接受严重程度显著下降、最大比值不增的中间尺寸进展；最终区域质量及几何验收保留。数值比较尺度为 float 比例量的 `1e-4` 与平方和的相对 `1e-6`（下限 `1e-12`），是数值比较保护，不是放宽几何、尺寸合格阈值。没有用操作数量判断质量成功。

该步骤使残余长边四条降为两条。算法停在 `no_safe_selected_split`。继续对两条真实输出边扫描发现：并非完全没有安全位置，而是安全参数区间被粗候选漏过。保存数据在 `results/phase13_residual/fraction_scan.json`。据此，粗候选全部不安全时启用最多 63 个额外 dyadic 候选（t=k/64）；仍要求两侧子三角形方向安全、非退化，尺寸评价及组合分裂检查不变。64 是候选工作预算，不宣称所有狭窄几何都可处理。运行时没有 patch ID 特例。

改动涉及 RegionQuality.h/cpp 的中间尺寸评价表达与判据、TriangleRefineBackend.cpp 的候选搜索、RawCudaBatch.h/cpp 的控制和诊断、CLI JSON 及针对性测试。未改分区、GPU 算子、接缝调度或窄带重建。关闭实验开关保留原尺寸判据与候选策略；诊断字段可继续使用。

后续应使用同一已完成 remesh 作为区域候选的 incumbent，在新产生共享边的相连区域内进行候选选择，保留有验证进展的区域并拒绝退化区域；不能仅在全局平均改善时替换全部结果。需要先统一 C++ 与独立审查的缺陷面积数值尺度，避免微小退化被其中一方漏掉。对困难窄带应优先验证已有区域重建在已改善邻域上的效果，避免重跑不相关 GPU 任务再次破坏邻域。上述是下一步设计，尚未实现或验证。
