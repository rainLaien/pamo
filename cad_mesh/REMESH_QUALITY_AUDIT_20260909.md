## 实现原因

```text
STL 分区 / 曲面拟合
  ├─ Plane → 二维约束三角化 → 通过验收 → 输出
  ├─ Cylinder / Cone → 参数域重建
  │                    ├─ 通过验收 → 输出
  │                    └─ 边界 / 法向 / 质量拒绝
  │                                ↓
  └─ Sphere / Torus / Freeform → 通用 CUDA 拆分、折叠、松弛
```

1. `analytic_remesh.py` 的圆柱现在按周向和轴向使用不同尺寸。周向还受 `radius * radians(normal_limit * 0.5)` 限制，默认相当于 2.5° 周向跨度；轴向仍可使用完整目标边长。`surface_rebuild.py` 用相应的归一化方向度量接受圆柱，允许很细长的三角形被认为质量良好。
2. 固定的 STL 边界仍保留原坐标，与新增的细密周向要求可能冲突。快速可行性预检只是提前发现失败；之前的逐数组对照证明，加入预检前后 1,698 个成功域和输出几何相同。回退增多不能归因于这项纯加速预检本身。
3. 旧解析算法没有参考网格法向偏差检查。当前新增检查后，圆锥仍主要按距离误差选点，并在生成后拒绝法向不合格的整片候选，缺少相应的局部修复。
4. 圆角是角色，不是独立曲面类型。圆柱圆角复用圆柱算法；圆环面和自由曲面圆角仍走通用 CUDA，目前没有独立的整片圆角重建算法。不能声称曾存在的完整圆角算法被最近删除。

当前低质量回退批次执行了很多拆分和折叠，但翻边为 0、松弛没有接受更新。仅让最长边合格、边长分布更均匀，不能保证三角形接近等边。

## 为什么不能只改布点比例

在 `111.stl` 的三个真实圆柱补丁上，仅将轴向尺寸限制为两倍周向，其他输入、边界和真实几何检查不变，平均形状质量由 0.038–0.092 提高到 0.620–0.651，但面数增加约 10–27 倍，三个候选全部违反现有 5° 法向限制；等距候选也全部失败。

局部检查发现，原始固定点离理想圆柱面约 0.0014–0.0049，而新点几乎精确落在理想曲面。密化后，这种细小偏移会形成局部很瘦、法向不协调的小三角形。直接密化并不能安全恢复高质量，也不能据此保证速度。

另一个隔离实验只移除圆柱周向跨度启发式上限，保留最终真实检查。三个补丁中一个通过实际 5° 检查（3.2646°），但普通三维平均质量从 0.71131 降到 0.58798；另两个仍分别因 5.4267°、5.8712° 拒绝。其中圆角候选的方向归一化质量达到 0.88651，而三维形状质量只有 0.05102。这证明该启发式会拒绝部分满足实际约束的候选，也证明只去掉它不足以恢复高质量。实验使用最新二进制输入，预处理拆分 10,280 次，与既有共享顶点前缀完全一致。

修复应优先协调共享边界附近的网格与曲面内部布点，恢复可验收的整片圆柱 / 圆锥重建；圆锥还需将法向要求纳入布点或局部重建。验收应分别核对真实几何误差、法向误差、普通三维三角形质量及低质量面比例，不只依赖方向归一化均值。现有性能缓存和输出精简可以继续保留。
