# CadMesh 原生保型 Remesh 与 CUDA 并行原理

## 1. 直观理解

可以把整个算法想成修建一张覆盖机械零件表面的三角形渔网。

- C++ 负责看懂零件：哪些区域是平面、圆柱、圆锥、球面、环面或自由曲面，哪些线是不能破坏的公共边界。
- CUDA 负责同时测量大量互不依赖的局部对象：例如几十万条边是否过长、每条边的中点在哪里、几十万个三角形的质量和法向是否合格。
- C++ 拓扑阶段负责真正剪开、合并和改接渔网。一次修改可能改变相邻边和三角形，所以必须处理写冲突和共享边界。

CUDA 像一组数量巨大的测量员，适合对很多边或三角形执行同一个公式。拓扑提交更像施工调度：两个工人如果同时修改同一个顶点，网格可能出现裂缝、重复面或非流形结构，因此当前由 C++ 统一提交。

## 2. 当前端到端流程

```text
                           ┌─────────────────────────────┐
STL ──► 清理与焊接 ───────►│ C++ MeshTopology            │
                           └──────────────┬──────────────┘
                                          │
                                          ▼
                           ┌─────────────────────────────┐
                           │ CAD 曲面识别与分区           │
                           │ Plane / Cylinder / Cone     │
                           │ Sphere / Torus / Freeform   │
                           └───────┬──────────────┬──────┘
                                   │              │
                         独立解析拟合任务       分区与约束提交
                                   │              │
                                   ▼              ▼
                          CUDA 批量数值拟合      C++
                                   │              │
                                   └──────┬───────┘
                                          ▼
                           ┌─────────────────────────────┐
                           │ 原生 NativeRemesher         │
                           │ 1. CUDA/C++ 统一采样共享边  │
                           │ 2. 解析 Patch 参数域重建    │
                           │ 3. 参数缝焊接及质量优化     │
                           │ 4. 冻结成功的解析 Patch     │
                           │ 5. Freeform 局部拓扑回退    │
                           │ 6. 全局相交与质量检查       │
                           └──────────────┬──────────────┘
                                          ▼
                                  remesh_result.ply
```

程序入口是 `app/cad_mesh_segment.cpp`。使用 `--remesh` 后，程序直接把内存中的分区交给 `src/NativeRemesher.cpp`，不生成 PLY/JSON 中间文件，也不启动 Python。CUDA remesh 内核位于 `src/CudaRemeshKernels.h`，以源码嵌入可执行程序，并由 `src/CudaAnalyticFitting.cpp` 中已有的 CUDA Driver + NVRTC 运行时动态编译和调用。构建阶段不需要 `nvcc` 或 MSVC `cl.exe`。

## 3. 数据模型与保型约束

原始 STL 经过焊接后形成共享索引网格：

```text
Vertices:  v0, v1, v2, ...
Faces:     (v0,v1,v2), (v2,v1,v3), ...
PatchIds:  每个三角形所属的曲面实例
Constraints:
            硬特征边 + 不同曲面之间的共享接口边
```

每个解析 Patch 保存拟合参数：

| 曲面 | 参数 | 点的投影方式 |
|---|---|---|
| Plane | 原点、法向 | 沿法向减去有符号距离 |
| Cylinder | 轴、半径 | 保留轴向坐标，将径向长度改成半径 |
| Cone | 轴、顶点、半角 | 在轴向—径向截面内做正交投影 |
| Sphere | 球心、半径 | 将球心到点的向量归一化到半径 |
| Torus | 轴、主半径、管半径 | 先投影到主圆，再投影到管圆 |

共享接口边的两个端点被锁定。拆分接口边时只创建一个全局中点 ID，相邻 Patch 引用同一个新顶点，因此不会因为两侧独立采样而产生裂缝。

自由曲面没有可靠的解析投影公式。当前实现为原始网格建立带 Patch 标签的 BVH；自由曲面的折叠点和松弛点投影到同一 Patch 的最近参考三角形。解析曲面候选可以先投影到精确解析面，但只有它到原 STL 同 Patch 表面的距离不超过 `MaximumDeviation` 时才接受，否则同样回投参考三角形。

## 4. 各 remesh 阶段的算法

### 4.1 建立唯一边和面邻接

C++ 遍历每个三角形的三条边，把端点按 `(minVertexId, maxVertexId)` 组成 64 位键，同一条共享边只保留一份。每条边记录最多两个邻接面，并标记非流形情况。

这一阶段目前在 CPU 执行，因为它同时构建哈希表和可变长度拓扑。GPU 也能通过“生成三倍边数组 → 规范化端点 → radix sort → reduce”实现，但只有把后续多个阶段都留在显存中时才划算。若每一轮都把排序结果传回 CPU，PCIe 传输和格式转换会抵消收益。

### 4.2 CUDA 长边筛选和中点计算

对每条唯一边 `e=(a,b)`，CUDA 线程执行：

```text
d = vertex[b] - vertex[a]
selected[e] = dot(d,d) > target_length²
midpoint[e] = 0.5 * (vertex[a] + vertex[b])
```

映射关系为“一条边对应一个 CUDA 线程”：

```text
thread 0 ─► edge 0 ─► length test + midpoint
thread 1 ─► edge 1 ─► length test + midpoint
thread 2 ─► edge 2 ─► length test + midpoint
   ...
thread N ─► edge N ─► length test + midpoint
```

这里适合 CUDA 的原因：

1. 每条边的输入和输出互不依赖，没有线程间写冲突。
2. 所有线程执行同一小段算术，分支很少，符合 SIMT 执行方式。
3. 边和顶点使用连续数组，能形成合并显存访问。
4. 边数通常达到十万或百万级，足以覆盖内核启动开销。
5. 比较使用边长平方，避免每条边调用平方根。

CUDA 返回 `selected[]` 和 `midpoint[]`。真正的拓扑拆分仍由 C++ 完成。

### 4.3 一致性长边拆分

C++ 为所有选中边建立唯一中点，然后根据一个三角形有 0、1、2 或 3 条边被选中，使用固定模板生成 1、2、3 或 4 个子三角形。

```text
一条边拆分                 三条边拆分

      c                         c
     / \                       / \
    /   \                     m---m
   a--m--b                   / \ / \
                            a---m---b
```

固定模板保证相邻三角形对同一共享边使用同一个中点。解析面内部的新点可以投影回拟合曲面；如果投影位移超过 `MaximumDeviation`，则保留原 STL 边上的中点。

拓扑提交没有直接放入当前 CUDA 内核，原因是一个边中点可能被两个面共享，输出面数又取决于每个面的拆分掩码。GPU 版本需要前缀和分配输出位置，并对共享边完成唯一编号。它可以实现，但必须作为一整套设备端拓扑管线实现，不能只把局部模板简单并行化。

### 4.4 短边折叠

候选边长度小于目标边长的 `0.65` 倍时，算法尝试把两个端点合并为中点，并投影回对应解析曲面。接受前检查：

- 边必须是普通流形内部边，且两侧属于同一个 Patch。
- 两个端点不能位于共享接口或硬特征约束上。
- 链接条件必须成立，避免折叠产生非流形拓扑。
- 受影响三角形不能退化或翻转。
- 新旧法向夹角不能超过默认的 10°。
- 新边不能超过目标边长。
- 局部三角形质量不能显著下降。

当前实现先建立“顶点到邻接面”的索引，每条候选只检查局部一环，不再扫描整个网格。

候选的几何计算可以在 CUDA 中并行，但多个候选可能共享顶点或邻接面。两个线程同时折叠相邻边会发生写冲突。完整 GPU 方案通常需要：候选打分、冲突图、并行独立集选择、批量提交、压缩和重新编号。当前让 CUDA 做无冲突的测量，让 C++ 做确定性的提交，优先保证共享边和 Patch 归属正确。

折叠批次完成后再次调用 CUDA 长边筛选。原因是两个各自合法且端点不相同的折叠，组合后仍可能形成一条新的过长边。修复阶段重新拆分这些边，避免在最终检查时直接失败。

### 4.5 质量翻边

两个同 Patch 三角形共享边 `(a,b)` 时，算法评估把对角线改成 `(c,d)`：

```text
原对角线 a-b              新对角线 c-d

c-------a                  c-------a
 \     /                    \   /
  \   /                      \ /
   \ /                        X
   / \                       / \
  /   \                     /   \
b-------d                  b-------d
```

只有新对角线提高局部最差三角形质量、长度不超标、不触碰约束边且法向变化不超过限制时才接受。

每条边的“是否值得翻转”可以在 CUDA 中并行评估，因为这是只读计算；同时提交仍存在相邻面冲突。未来可在 GPU 上为候选建立优先级，选择不共享面的并行独立集，再一次提交一批翻边。

### 4.6 解析曲面松弛

对非约束、只属于一个解析 Patch 的顶点，先计算邻点平均值，再做阻尼移动：

```text
p_candidate = 0.8 * p_old + 0.2 * average(neighbor_positions)
p_surface   = project_to_analytic_surface(p_candidate)
```

只有邻接面总质量不下降、所有边长合格、投影位移合格且法向变化不超过 10°时才接受。

这一阶段的大部分计算适合 CUDA：

- 邻点求和可以使用 CSR 邻接表，一顶点一线程。
- Plane/Cylinder/Cone/Sphere/Torus 投影是一顶点一线程。
- 邻接面质量和法向检查是一面一线程，或一顶点处理其 CSR 面列表。
- 接受标志可以批量计算，再对无冲突顶点统一提交。

当前在 C++ 中执行，是因为拓扑阶段仍在主存；单独把一次只有 3 轮的松弛上传到 GPU，会产生重复上传。每个候选移动还会查询当前网格 BVH，拒绝与任何非邻接三角形相交的结果。同一批已接受候选使用目标边长尺度的空间哈希互相检查，避免两个分别合法的移动组合后产生穿透。下一阶段优化应让边表、面表和参考 BVH 在一次 remesh 周期内常驻显存，再把长边筛选、投影、质量检查、碰撞查询和松弛合并成少量 CUDA 批次。

### 4.7 三角形质量和最终检查

当前使用的三角形质量为：

```text
q = 2√3 · |(b-a) × (c-a)|
    ───────────────────────
     |a-b|² + |b-c|² + |c-a|²
```

`q=1` 表示等边三角形，接近 `0` 表示细长或退化三角形。最终统计平均质量、最低质量、最小角和最大边长，并报告是否达到 `TargetMeanTriangleQuality`。

该统计天然适合 CUDA：每个面独立计算质量、三个角和三条边长，然后使用并行 reduction 求和、最小值和最大值。当前只在结尾执行一次，CPU 成本相对较小；如果优化循环需要频繁依据全局质量决定是否继续，迁移到 CUDA 的收益会明显增加。

## 5. CUDA 解析曲面拟合为什么有效

分区阶段需要为大量局部邻域尝试 Cylinder、Cone、Sphere 和 Torus 参数。不同种子和不同初始参数之间彼此独立，每个任务都重复执行：

1. 计算样本点残差。
2. 计算有限差分 Jacobian/Hessian。
3. 求解小型阻尼系统。
4. 执行回溯并更新参数。
5. 返回误差和候选模型。

当前实现将多个种子组成批次，每个初值由一个 CUDA block 处理，block 内线程并行累加样本残差。这样可以减少 CPU 与 GPU 每轮往返。日志中的 `queued jobs`、`reused jobs`、`mean batch seeds` 和 `transfer+kernel+wait` 对应这一阶段。

适合 GPU 的核心原因不是“用了复杂数学”，而是同一种数学要在大量独立种子和样本上重复。批次过小时，内核启动和传输占比会上升，因此预取器会合并邻域并复用完全相同的拟合输入。

## 6. 当前 CUDA 边界与下一步迁移优先级

| 阶段 | 当前执行位置 | CUDA 适合度 | 原因与建议 |
|---|---|---:|---|
| 解析种子非线性拟合 | CUDA | 高 | 种子独立，样本残差可并行归约 |
| 长边筛选与中点 | CUDA | 高 | 一边一线程，无写冲突 |
| 解析曲面点投影 | CPU | 高 | 一点一线程；应与松弛候选合并成一个内核 |
| 面质量、法向和边长 | CPU | 高 | 一面一线程，适合 reduction |
| 邻点平均和松弛候选 | CPU | 高 | 使用 CSR 后可一顶点一线程 |
| 最近参考面查询 | CPU BVH | 高 | 已按 Patch 限制最近面；后续可将同一 BVH 查询迁移到 CUDA |
| 自相交查询 | CPU BVH + 批内空间哈希 | 高 | 候选三角形独立，适合迁移到 CUDA 批量查询 |
| 唯一边构建 | CPU | 中 | GPU 需要 sort/reduce，适合显存常驻方案 |
| 拆分拓扑提交 | CPU | 中 | 需要共享中点编号、scan 和变长输出 |
| 折叠/翻边提交 | CPU | 中低 | 候选冲突，需要独立集和确定性提交 |
| PLY 输出 | CPU | 低 | 文件系统和文本格式不适合 GPU |

性能上最值得继续迁移的组合不是单个小函数，而是：

```text
网格一次上传
  → GPU 常驻边/面/解析参数
  → 长短边候选 + 投影 + 面质量 + 法向检查
  → GPU 冲突过滤
  → C++ 或 GPU 批量拓扑提交
  → 若拓扑改变则设备端重建邻接
  → 最终一次下载
```

这样能减少目前每个拆分轮次的主机打包、上传和回读。如果仍由 C++ 每轮重建拓扑，那么把更多很小的公式分别做成 CUDA 调用，反而可能因为 PCIe 传输和同步变慢。

## 7. 常见误区和注意点

最大的误区是认为“把循环改成 CUDA kernel 就一定更快”。CUDA 只有在任务数量足够大、每个任务相对独立、数据连续并且能减少 CPU/GPU 往返时才有优势。动态网格拓扑包含大量共享写入和变长输出，必须先解决冲突选择、前缀和、压缩以及稳定编号。

另一个容易忽略的问题是保型条件不能只在移动前检查。拆分、折叠、翻边和松弛每次提交后都可能改变邻域，必须重新检查最大边长、法向、退化面和共享边界。当前流程在折叠后和最终输出前重新执行长边修复，就是为了避免局部候选单独合法、组合后却违反全局边长条件。

`TargetMeanTriangleQuality=0.8` 是最终平均质量目标和报告阈值，不代表每个三角形都达到 0.8。狭窄边界、CAD 曲面交汇和必须保留的短特征边会限制局部质量。若要把它变成严格成功条件，需要同时定义最低质量、最小角、允许增加的面数以及无法达到目标时的处理方式，否则算法可能为了追求平均值而持续细分或直接失败。

## 8. 相关代码

- `app/cad_mesh_segment.cpp`：命令行、全流程计时和最终输出入口。
- `include/CadMesh/NativeRemesher.h`：原生 remesh 配置、结果和统计接口。
- `src/NativeRemesher.cpp`：约束保持、拆分、折叠、翻边、投影、松弛和质量统计。
- `src/AnalyticPatchRemesher.cpp`：Plane、Cylinder、Cone、Sphere 和 Torus 的整块参数域重建、周期缝焊接及参数域质量优化。
- `include/CadMesh/AnalyticPatchRemesher.h`：解析 Patch 重建接口和回退统计。
- `src/CudaRemeshKernels.h`：嵌入式 CUDA 长边筛选和中点内核源码。
- `src/CudaAnalyticFitting.cpp`：分区解析拟合与 remesh 共用的 CUDA Driver + NVRTC 运行时。
- `src/CudaAnalyticKernels.h`：解析模型拟合 CUDA kernel 源码。
- `CMakeLists.txt`：原生 C++ 可执行程序构建；CUDA 内核在运行时编译。
