## 原因与修改

1. **短边折叠重复检查曲面。** 原先先按最终法向阈值检查，再无缓存按更严格的候选阈值重查。改为使用两者的最小阈值一次检查，复用通过和拒绝结果；无需缓存时也采用相同阈值。两种折叠方向共用原面几何计算，并先排除拓扑、方向、边长或质量已不合格的候选。
2. **大模型曲面缓存可能直接失效。** 原缓存将曲面和三个顶点 ID 打包成一个整数，超过 int64 范围时停用。改为分别保存完整整数键，哈希冲突仅替换条目，不会把不同三角形当成同一个；最多 2^20 个槽。CUDA 内核分两步读取/选举和写回，减少排序、动态抽取和 CPU 同步。
3. **布尔检查求了过多最近点信息。** 法向仍使用质心的精确最近支撑，其余六个距离样本改为在完整所属曲面 BVH 中搜索阈值内支撑，找到后即可结束。保留全部七个样本和原容差；详细诊断、最终验证继续返回完整距离与法向统计。
4. **relax 回溯重复构建相同边集合。** 坐标变化期间拓扑固定，现共用一次构建的边、顶点度数和每个候选位置的质量数组。迭代次数、回溯和接受条件保留。
5. **批次与全模型重复扫描。** 默认批次从 40,000 面提高到 200,000 面，连通遍历交给 SciPy；批次之间保留 PyTorch 的可复用分配缓存。曲面分组和解析图调度一次建立索引，解析图只查询自身边，无需每个图扫描全部约束或分配全模型顶点映射。
6. **边界处理和解析图中的 CPU 开销。** 边界细分只为约束边建立可变关联集合，整数数组处理全局拓扑；唯一边使用一维整数键。解析图顶点映射和固定边匹配批量处理，距离采样分块复用同一 AABB。
7. **重复文本格式化和逐记录解析。** PLY 分块解析，扩展格式保留原解析路径；三份 ASCII PLY 共用顶点文本，面记录整块格式化并缓冲写出。保持 17 位坐标、字段、文件名和索引。输入和导出时的几何、拓扑及来源约束检查保留。

默认批次增大后，计算接缝和采样分配会变化；候选处理的浮点运算组织也有变化，输出不承诺逐面与旧版本相同。共享几何边保护、目标边长和误差要求仍由原有条件及最终检查约束。

## Warp 兼容修复

用户首次运行新增缓存时报 `_validate_cached` 中 `wp.atomic_min` 的编译错误。项目内置 Warp 1.0.0-beta.2 对该原子操作的索引及整数值要求 int32；64 位调用不匹配，随后其错误格式化代码又触发 `array.__name__` 异常。缓存槽索引和写入者计数改用 int32，完整顶点/曲面键仍为 int64，坐标和 BVH 距离仍为 float64。

## 用户运行入口

复用已有 partition，只计量 remesh，可从项目根目录运行以下命令（输出目录请使用新路径）：

```powershell
.\cad_mesh\run_remesh.ps1 `
  -PartitionDirectory .\cad_mesh\debug\111\partition `
  -OutputDirectory .\cad_mesh\debug\111\remesh_fast_20260909 `
  -TargetEdgeLength 12 -FlipPasses 0
```

`-BatchFaceLimit` / `--batch-face-limit` 可覆盖默认的 200,000 面。阶段曲面诊断由 `PAMO_TRACE_SURFACE_VALIDATION` 控制，默认关闭；开启会额外运行各阶段的全量诊断。最终曲面、拓扑和边长检查始终保留。

观察 CLI 的 `[remesh] Timing` 总时间及新增 `[surface] Timing` 分项；报告中保留 `stats.batches[].batch_seconds` 和 `stats.timing_breakdown_seconds`。`remesh_file.py` / `remsh.ps1` 会额外执行分区，完整流程的总耗时需要另计。
